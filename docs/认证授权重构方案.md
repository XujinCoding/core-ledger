# Core-Ledger 认证授权重构方案

## 一、现状分析

### 1.1 当前架构

```
请求 → JwtAuthenticationFilter → AuthenticationInterceptor → @RequireIdentity 切面 → Controller
         ↓                              ↓                           ↓
    SecurityContextHolder          检查临时Token限制            检查身份类型权限
    AppSessionContext
```

### 1.2 存在的问题

#### 问题 1：双重上下文维护（不优雅）
- **SecurityContextHolder**：Spring Security 标准，存储 Authentication 对象
- **AppSessionContext**：自定义 ThreadLocal，存储 SessionInfo 对象
- **现状**：业务代码主要使用 AppSessionContext，SecurityContextHolder 形同虚设
- **问题**：维护两套上下文，增加复杂度和出错风险

#### 问题 2：权限控制层次重复
- **SecurityConfig**：URL 级别的权限控制（permitAll/authenticated）
- **AuthenticationInterceptor**：拦截器检查临时 Token 限制
- **@RequireIdentity 切面**：方法级别的身份类型检查
- **问题**：三层控制有功能重叠，AuthenticationInterceptor 可以被 Spring Security 替代

#### 问题 3：代码 Bug
**JwtAuthenticationFilter.java:60-63** 逻辑错误：
```java
if (userInfo != null) {  // ❌ 应该是 userInfo == null
    log.warn("Token 在 Redis 中不存在或已过期");
} else {
    // 构建 SessionInfo
}
```

#### 问题 4：@RequireIdentity 切面可以优化
- 当前使用自定义切面实现
- Spring Security 提供了 @PreAuthorize 注解，功能更强大
- 可以统一到 Spring Security 的权限体系中

## 二、重构方案

### 方案一：完全拥抱 Spring Security（推荐）⭐

#### 2.1.1 核心思想

**去掉 AppSessionContext，完全使用 Spring Security 的 SecurityContextHolder**

- 将用户信息存储在 Spring Security 的 `Authentication` 对象中
- 使用自定义的 `UserPrincipal` 类封装用户详细信息
- 业务代码通过 `SecurityContextHolder` 或方法注入获取用户信息

#### 2.1.2 架构设计

```
请求 → JwtAuthenticationFilter → Spring Security FilterChain → Controller
         ↓
    SecurityContextHolder (存储 UserPrincipal)
         ↓
    @PreAuthorize 注解 (方法级权限控制)
```

#### 2.1.3 核心组件设计

##### 1. UserPrincipal（用户主体对象）

```java
@Data
@Builder
public class UserPrincipal implements UserDetails {
    private Long userId;
    private String token;
    private Long merchantId;
    private Long customerId;
    private IdentityType identityType;
    
    // 是否已选择身份（用于临时Token限制）
    public boolean hasSelectedIdentity() {
        return identityType != null && 
               (merchantId != null || customerId != null);
    }
    
    // 是否是商户身份
    public boolean isMerchantOwner() {
        return IdentityType.MERCHANT_OWNER.equals(identityType);
    }
    
    // 是否是客户身份
    public boolean isCustomer() {
        return IdentityType.CUSTOMER.equals(identityType);
    }
    
    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        if (identityType == null) {
            return Collections.singletonList(
                new SimpleGrantedAuthority("ROLE_TEMP_USER")
            );
        }
        return Collections.singletonList(
            new SimpleGrantedAuthority("ROLE_" + identityType.name())
        );
    }
    
    @Override
    public String getPassword() { return null; }
    
    @Override
    public String getUsername() { return String.valueOf(userId); }
    
    @Override
    public boolean isAccountNonExpired() { return true; }
    
    @Override
    public boolean isAccountNonLocked() { return true; }
    
    @Override
    public boolean isCredentialsNonExpired() { return true; }
    
    @Override
    public boolean isEnabled() { return true; }
}
```

```java
public class SecurityUtils {
    
    /**
     * 获取当前用户主体
     */
    public static UserPrincipal getCurrentUser() {
        Authentication authentication = SecurityContextHolder
            .getContext().getAuthentication();
        if (authentication != null && 
            authentication.getPrincipal() instanceof UserPrincipal) {
            return (UserPrincipal) authentication.getPrincipal();
        }
        throw new UnauthorizedException("未登录或登录已过期");
    }
    
    /**
     * 获取当前用户ID
     */
    public static Long getCurrentUserId() {
        return getCurrentUser().getUserId();
    }
    
    /**
     * 获取当前商户ID
     */
    public static Long getCurrentMerchantId() {
        return getCurrentUser().getMerchantId();
    }
    
    /**
     * 获取当前客户ID
     */
    public static Long getCurrentCustomerId() {
        return getCurrentUser().getCustomerId();
    }
    
    /**
     * 获取当前身份类型
     */
    public static IdentityType getCurrentIdentityType() {
        return getCurrentUser().getIdentityType();
    }
    
    /**
     * 获取当前Token
     */
    public static String getCurrentToken() {
        return getCurrentUser().getToken();
    }
    
    /**

     */

        try {
            return getCurrentUser().hasSelectedIdentity();

            return false;
        }
    }
}
```

##### 3. 优化后的 JwtAuthenticationFilter

```java
@Override
protected void doFilterInternal(HttpServletRequest request,
                                HttpServletResponse response,
                                FilterChain filterChain) 
        throws ServletException, IOException {
    try {
        String token = extractTokenFromRequest(request);
        
        if (StrUtil.isNotBlank(token)) {
            // 1. 校验 JWT 签名
            if (jwtTokenProvider.validateToken(token)) {
                // 2. 从 Redis 获取用户信息
                CurrentUserIdentityInfo userInfo = 
                    tokenUtil.getCurrentUserIdentityInfo(token);
                
                if (userInfo != null) {  // ✅ 修复 bug
                    // 3. 构建 UserPrincipal
                    UserPrincipal principal = UserPrincipal.builder()
                        .userId(userInfo.getUserId())
                        .token(token)
                        .merchantId(userInfo.getMerchantId())
                        .customerId(userInfo.getId())
                        .identityType(userInfo.getIdentityType())
                        .build();
                    
                    // 4. 设置 Spring Security 上下文
                    UsernamePasswordAuthenticationToken authentication =
                        new UsernamePasswordAuthenticationToken(
                            principal,
                            null,
                            principal.getAuthorities()
                        );
                    
                    authentication.setDetails(
                        new WebAuthenticationDetailsSource()
                            .buildDetails(request)
                    );
                    
                    SecurityContextHolder.getContext()
                        .setAuthentication(authentication);
                }
            }
        }
    } catch (Exception e) {
        log.error("Token 认证失败: {}", e.getMessage(), e);
    }
    
    try {
        filterChain.doFilter(request, response);
    } finally {
        // 清空上下文
        SecurityContextHolder.clearContext();
    }
}
```

##### 5. SecurityConfig 优化

```java
@Configuration
@EnableWebSecurity
@EnableMethodSecurity  // 启用方法级安全
@RequiredArgsConstructor
public class SecurityConfig {
    
    private final JwtAuthenticationFilter jwtAuthenticationFilter;
    private final JwtAuthenticationEntryPoint jwtAuthenticationEntryPoint;
    
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(AbstractHttpConfigurer::disable)
            .exceptionHandling(exception -> exception
                .authenticationEntryPoint(jwtAuthenticationEntryPoint)
            )
            .sessionManagement(session -> session
                .sessionCreationPolicy(SessionCreationPolicy.STATELESS)
            )
            .authorizeHttpRequests(auth -> auth
                // 公开接口
                .requestMatchers(
                    "/api/auth/wechat-login",
                    "/api/auth/merchant/wechat/register",
                    "/api/auth/customer/wechat/register",
                    "/api/sms/send",
                    "/api/auth/register",
                    "/api/auth/login",
                    "/api/auth/send-sms-code",
                    "/api/addresses/**",
                    "/health",
                    "/actuator/**",
                    "/doc.html",
                    "/swagger-ui/**",
                    "/v3/api-docs/**",
                    "/webjars/**"
                ).permitAll()
                
                // 临时Token可访问的接口（未选择身份）
                .requestMatchers(
                    "/api/auth/switch-identity",
                    "/api/auth/identities",
                    "/api/auth/logout",
                    "/api/auth/current-user"
                ).authenticated()
                
                // 其他接口需要已选择身份
                .anyRequest().access(
                    new WebExpressionAuthorizationManager(
                        "@authz.hasSelectedIdentity()"
                    )
                )
            )
            .addFilterBefore(jwtAuthenticationFilter, 
                UsernamePasswordAuthenticationFilter.class);
        
        return http.build();
    }
    
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

#### 2.1.5 迁移步骤

1. **创建新组件**
   - 创建 `UserPrincipal` 类
   - 创建 `SecurityUtils` 工具类
   - 创建 `CustomAuthorizationService` 权限评估器

2. **修改 JwtAuthenticationFilter**
   - 修复 bug（第 60 行）
   - 改为设置 `UserPrincipal` 到 SecurityContext
   - 去掉 `AppSessionContext.setSessionInfo()`

3. **优化 SecurityConfig**
   - 添加临时 Token 白名单的访问控制
   - 配置 `.anyRequest().access(@authz.hasSelectedIdentity())`

4. **替换业务代码**
   - 全局搜索 `AppSessionContext.getUserId()` 替换为 `SecurityUtils.getCurrentUserId()`
   - 全局搜索 `AppSessionContext.getMerchantId()` 替换为 `SecurityUtils.getCurrentMerchantId()`
   - 全局搜索 `AppSessionContext.getCustomerId()` 替换为 `SecurityUtils.getCurrentCustomerId()`
   - 全局搜索 `AppSessionContext.getIdentityType()` 替换为 `SecurityUtils.getCurrentIdentityType()`

5. **替换权限注解**
   - 将 `@RequireIdentity(IdentityType.MERCHANT_OWNER)` 替换为 `@PreAuthorize("@authz.isMerchantOwner()")`
   - 将 `@RequireIdentity(IdentityType.CUSTOMER)` 替换为 `@PreAuthorize("@authz.isCustomer()")`

6. **删除旧组件**
   - 删除 `AuthenticationInterceptor`
   - 删除 `WebMvcConfig` 中的拦截器配置
   - 删除 `@RequireIdentity` 注解
   - 删除 `PermissionAspect` 切面
   - 删除 `AppSessionContext` 类

#### 2.1.6 优点

✅ **标准化**：完全符合 Spring Security 最佳实践  
✅ **简洁**：只维护一套上下文，代码更清晰  
✅ **安全**：利用 Spring Security 的成熟机制  
✅ **灵活**：@PreAuthorize 支持复杂的权限表达式  
✅ **可测试**：更容易编写单元测试和集成测试  

#### 2.1.7 缺点

⚠️ **改动量大**：需要修改所有使用 AppSessionContext 的地方  
⚠️ **学习成本**：团队需要理解 Spring Security 的 Authentication 机制

### 方案二：保留 AppSessionContext，优化其他部分（折中方案）

#### 2.2.1 核心思想

**保留 AppSessionContext 作为业务层的便捷工具，但去掉冗余的拦截器和切面**

- 保留 AppSessionContext（业务代码不需要大改）
- 去掉 AuthenticationInterceptor 和 WebMvcConfig
- 用 SecurityConfig 的 URL 级别控制替代拦截器
- 用 @PreAuthorize + 自定义评估器替代 @RequireIdentity 切面

#### 2.2.2 架构设计

```
请求 → JwtAuthenticationFilter → Spring Security FilterChain → Controller
         ↓
    SecurityContextHolder (存储 UserPrincipal)
    AppSessionContext (存储 SessionInfo) ← 保留
         ↓
    @PreAuthorize 注解 (方法级权限控制)
```

#### 2.2.3 核心组件设计

##### 1. 保留 AppSessionContext

不做修改，继续使用 ThreadLocal 存储 SessionInfo

##### 2. 创建 SecurityUtils（桥接层）

## 四、推荐建议

### 4.1 短期建议（1-2 周内）

**采用方案二**，原因：
1. 改动量小，可以快速完成
2. 风险可控，不影响现有业务
